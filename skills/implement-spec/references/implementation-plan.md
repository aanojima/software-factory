# Implementation plan contract

Create the plan only after reading the spec and material exploration findings.

Include:

1. **Goal and non-goals** copied or faithfully summarized from the spec.
2. **Repository findings** with file and symbol evidence.
3. **Chosen approach** and why it fits existing architecture.
4. **Change set** organized by component or file.
5. **Acceptance traceability** mapping every criterion to implementation and validation.
6. **Migration, rollout, and rollback** when applicable.
7. **Risks and mitigations** based on actual affected surfaces.
8. **Validation commands and evidence expected**.
9. **Open technical questions** that can be resolved during execution.
10. **Deviations** from implementation suggestions in the spec, without changing product intent.

Prefer the smallest correct change. Do not optimize for an aesthetically ideal architecture when the existing system has a safe established pattern.
